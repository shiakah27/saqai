# SAQAI | سَقاي — Intelligence Behind Every Drop

> النسخة العربية من الـREADME. The English version is in [README.md](README.md).


محطة استشعار محلية تقرأ الطقس والمطر ورطوبة التربة لحظيًا، ونموذج ذكاء اصطناعي مدرّب على مناخ الرياض
يتنبأ بالمطر خلال 3 ساعات. عقدة التشغيل (ESP32 #2) تجمع الحساسات والتنبؤ وتقرر **بنفسها** أي منطقة هي الأحوج،
وتفتح صمامها وحده. إذا بدأ المطر فعلًا، يتوقف كل شيء فورًا.

```
Historical Riyadh CSV ──► OFFLINE training ──► rain_model_v1 (ملف فقط، لا يُقرأ وقت التشغيل)

ESP32 #1  عقدة الحساسات                     Backend (Node)                     ESP32 #2  عقدة التشغيل
BME280 + MH-RD rain + Soil ×3                                             Relay → Pump + 3 Valves
   │ POST /api/readings  كل 2 ث  ─────►  live frame + PostgreSQL  ◄──── GET /api/actuator/inputs كل 1 ث
   │ POST /api/rain-event  فوري  ─────►  RAIN_LOCKOUT                       │ saqai_decision.h يقرر:
                                         │ كل 30 د                          │  - كل منطقة: IRRIGATE/DEFER/SKIP/HOLD
                                         ▼                                  │  - يختار الأحوج فقط → صمام واحد
                                  AI service (Python) → rain_probability    │ POST /api/actuator/decisions
                                         │                                  │ POST /api/actuator/run (started/finished)
                                         ▼
                                  Dashboard (React, SSE مباشر)

لوحة المطر تكشف الماء ─► RAIN_LOCKOUT ─► عقدة التشغيل تراه في الاستعلام التالي ─► Pump OFF ≤ 1 ث
```

كل البيانات في التشغيل تأتي من الحساسات الحقيقية. البيانات التاريخية تُستخدم للتدريب فقط.

## ابدئي من هنا

**`docs/code-guide.md`**: خريطة الكود بالعربي، وين كل ملف، ورحلة القراءة من الحساس إلى الصمام. وكل ملف كود فيه شرح بالعربي فوق كل دالة.

**`docs/bring-up.md`**: التشغيل الفعلي خطوة بخطوة، من الشبكة إلى رفع الكود على اللوحتين، ثم الفحص الشامل، ثم المعايرة، ثم اختبار إيقاف المطر.

بعد الإعداد الأول، التشغيل اليومي ضغطة واحدة: `start.bat` على Windows، أو `./start.sh` على macOS.
افتحي العنوان الذي يطبعه الـBackend، مثل `http://192.168.43.20:3000`.

## ماذا يوجد في المستودع

| المجلد | المحتوى |
|---|---|
| `esp32/sensor_node/` | ESP32 #1: كل الحساسات، إطار قراءات كل 2 ث، حدث مطر فوري |
| `esp32/actuator_node/` | ESP32 #2: المضخة والصمامات، و**محرك القرار** `saqai_decision.h` يعمل على اللوحة نفسها |
| `esp32/tests/` | 35 اختبار وحدة لمحرك القرار (C++ على اللابتوب) + `decide_cli` الذي يستخدمه اختبار e2e |
| `backend/src/` | Express: يستقبل القراءات، يبث مباشرة (SSE)، يجهز مدخلات القرار، قفل المطر في `safetyService.js` و`rainLockout.js` |
| `ai/` | `features.py`، `train.py`، `calibration.py`، `explain.py`، خدمة FastAPI، النموذج وتقريره |
| `database/` | المخطط والإعداد الأولي للأجهزة والمناطق |
| `frontend/` | لوحة التحكم المباشرة: المزرعة الحية، مسار القرار، التنبؤ، عمليات الري، الصيانة |
| `tools/doctor.js` | فحص شامل: `cd backend && npm run doctor` |
| `docs/` | خريطة الكود، التشغيل، المعمارية، الـAPI، العتاد، المعايرة، الاختبارات، سيناريو العرض |

## الاختبارات

```bash
cd backend
npm run test:firmware   # 35 اختبار لمحرك القرار الذي يعمل على ESP32 #2
npm test                # اختبارات آلة حالات المطر
python ../ai/src/train.py   # يعيد التدريب ويكتب تقرير النموذج
```

اختبار الأمان طرف-لطرف (`npm run e2e`، 36 فحصًا، يستخدم محرك القرار الحقيقي بلغة C++) يُشغّل على **قاعدة بيانات اختبار منفصلة** فقط. الطريقة في `docs/test-plan.md`.

## نتائج النموذج (فترة اختبار لم يرها: يوليو 2024 → سبتمبر 2026)

| | |
|---|---|
| الخوارزمية | Random Forest (أفضل PR-AUC من 5 مرشحين) + Isotonic calibration |
| السؤال | هل ستمطر (≥ 0.1 ملم) خلال 3 ساعات، والجو جاف الآن؟ |
| PR-AUC | 0.172، أي 10 أضعاف الصدفة (نسبة المطر 1.7%) |
| ROC-AUC | 0.929 |
| عتبة القرار | 8% (اختيرت حسب تكلفة الخطأ: التأجيل الخاطئ يؤخر الري 3 ساعات بالكثير) |
| بدايات مطر تنبّأ بها قبل 3 ساعات | 48 من 77 (62%) |
| مقارنة بقواعد بسيطة | أفضل من "رطوبة ≥ 55%" ومن "رطوبة + ضغط ينزل" ومن المتوسط التاريخي (`ai/reports/rain_model_v1.md`) |

النموذج يفوته جزء من المطر (حوالي 4 من كل 10 بدايات). لهذا السبب حساس المطر هو طبقة الأمان، وليس الذكاء الاصطناعي.
والنموذج يحتاج 3 ساعات من قراءات المحطة الحقيقية قبل أول تنبؤ. قبلها تروي عقدة التشغيل حسب التربة وحدها (`NO_FORECAST`).

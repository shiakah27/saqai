# التشغيل الفعلي خطوة بخطوة

هذا الدليل يأخذك من الصفر إلى نظام يعمل على العتاد الحقيقي. نفذي الخطوات بالترتيب، ولا تنتقلي لخطوة قبل أن تري النتيجة المكتوبة تحتها.

## 0. الشبكة (مرة واحدة)

1. شغّلي Hotspot من جوال على **2.4GHz**، فـESP32 لا يرى شبكات 5GHz.
2. وصّلي اللابتوب بالـHotspot نفسه.
3. Windows فقط: اسمحي للمنفذين 3000 و8000 في الـFirewall. بدون ذلك يرفض اللابتوب اتصال ESP32 بصمت.
   - PowerShell كمسؤول:
     `New-NetFirewallRule -DisplayName SAQAI -Direction Inbound -Protocol TCP -LocalPort 3000,8000 -Action Allow`

## 1. اللابتوب (مرة واحدة)

```bash
cp .env.example .env
cp .env.example backend/.env          # غيّري DEVICE_API_KEY وADMIN_API_KEY وكلمة مرور قاعدة البيانات
python -m venv .venv                  # Windows: py -3.12 -m venv .venv
.venv/bin/pip install -r ai/requirements.txt          # Windows: .venv\Scripts\pip ...
cd backend && npm install && cd ../frontend && npm install && npm run build && cd ..
```

> **إذا كنتِ شغّلتِ النسخة الأولى من قبل** (weather station + irrigation node): المخطط تغير. صفّري قاعدة البيانات مرة واحدة:
> `docker compose down -v && docker compose up -d` (يمسح القراءات القديمة فقط). الـBackend يطبع هذه التعليمة إذا وجد المخطط القديم.

## 2. التشغيل (كل مرة)

Windows: انقري مرتين على `start.bat`. macOS: نفذي `./start.sh`.

**ماذا يجب أن تري** في آخر سطور الـBackend:

```
SAQAI backend listening on port 3000
  dashboard + ESP32 BACKEND_URL → http://192.168.43.20:3000   (Wi-Fi)
```

هذا العنوان هو ما تكتبينه في `BACKEND_URL` على اللوحتين، وتفتحين به لوحة التحكم من أي جهاز على الشبكة.
عنوان Hotspot قد يتغير إذا أُعيد تشغيل الجوال، فتأكدي منه في كل مرة.

## 3. رفع الكود على ESP32 (مرة واحدة لكل لوحة)

1. Arduino IDE ← Boards Manager ← **esp32 by Espressif** (الإصدار 3.x). الكود جُرّب عليه بالترجمة.
2. Library Manager: **Adafruit BME280 Library** (توافق على تثبيت التوابع)، و**ArduinoJson** (v7).
3. في كل مجلد من `esp32/sensor_node` و`esp32/actuator_node`: انسخي `secrets.example.h` إلى `secrets.h` واملئي اسم الشبكة وكلمتها، و`BACKEND_URL` من الخطوة 2، و`DEVICE_API_KEY` نفسه الموجود في `backend/.env`.
4. Board: **ESP32 Dev Module**، والمنفذ الصحيح، ثم Upload. إذا علق عند `Connecting....`، اضغطي زر BOOT.

### ESP32 #1 عقدة الحساسات: Serial Monitor على 115200

```
SAQAI sensor node sn-2.0.0
[bme280] ok
[wifi] connected, IP 192.168.43.57
[rain] MH-RD AO=4095 (dry≈4095 wet≈1500) DO=dry
[frame] 33.4°C 15% 941.3hPa rain=0 L0 (AO 4095, wet 0%, DO dry) soil 31.2%(2410) 44.0%(2050) 27.5%(2470) → HTTP 201
```

| إذا رأيتِ | السبب والحل |
|---|---|
| `[bme280] NOT FOUND` | SDA→21 وSCL→22، والعنوان 0x76 أو 0x77 |
| `AO 0` واللوحة جافة، أو `[rain] AO reads ~0 but DO says dry` | سلك AO مفصول (المقاومة 100kΩ سحبته إلى 0)، فالنظام في قفل المطر ولن يروي. افحص AO→GPIO35 |
| `AO` يتغير عشوائيًا واللوحة جافة | سلك AO مفصول ولا توجد مقاومة 100kΩ. ركّبها بين AO وGND |
| `DO WET` دائمًا واللوحة جافة | البرغي الأزرق حساس جدًا: لفّه حتى ينطفئ LED الموديول واللوحة جافة |
| `wet` لا يتعدى 15% مع رش الماء | المعايرة: سجّل AO واللوحة مبللة في `RAIN_WET_RAW` (docs/calibration.md) |
| تربة `--(4095)` أو `--(0)` | الحساس مفصول أو القراءة خارج 300..3800: افحصي AOUT على 32/33/34 |
| `HTTP -1` | BACKEND_URL خطأ، أو الـFirewall، أو اللابتوب على شبكة أخرى |
| `HTTP 401` | DEVICE_API_KEY لا يطابق backend/.env |
| `HTTP 400` ورسالة عن الضغط | قراءة ضغط غير منطقية، فافحصي الحساس |

الإطار يُرسل كل ثانيتين، ويُطبع كل 30 ثانية أو عند أي خطأ (الرقم بين القوسين = ADC الخام للمعايرة). في اللوحة: شارة "عقدة الحساسات" خضراء، والأرقام تتحرك كل ثانيتين، والشارة "مباشر".

### ESP32 #2 عقدة التشغيل: ارفعي الكود والمضخة **غير موصولة بالكهرباء**

```
SAQAI actuator node an-2.0.0
[wifi] connected 192.168.43.58
[run] START zone 1 for 14s (BELOW_TARGET)        ← عندما تقرر أن منطقة تحتاج
[run] STOP zone 1 completed TARGET_REACHED after 9.2s
```

| إذا رأيتِ | السبب والحل |
|---|---|
| `[poll] backend unreachable` | نفس أسباب `HTTP -1` أعلاه. المضخة تبقى مطفأة |
| `[run] zone N refused by backend` | النظام في قفل المطر أو انتظار أو عطل: هذا صحيح، لا ماء |
| لا يبدأ أي ري | افتحي "مسار القرار" في اللوحة: يوضح السبب لكل منطقة (التربة فوق الهدف، تأجيل بسبب تنبؤ المطر، فترة التسرب...) |

في اللوحة: شارة "عقدة التشغيل" خضراء، وقسم "مسار القرار" يعرض قرار اللوحة لكل منطقة، ومنطقة واحدة فقط "تُروى" والبقية "ينتظر دوره".

## 4. الفحص الشامل

```bash
cd backend && npm run doctor
```

يجب أن ينتهي بـ`Everything looks good`، ما عدا "station history x/180 min" في الساعات الثلاث الأولى.

## 5. المعايرة على العتاد

افتحي صفحة **الصيانة** من الرابط المباشر `http://<عنوان-اللابتوب>:3000/#/maintenance` (مخفية من الشريط عن الزوار)، وأدخلي `ADMIN_API_KEY`.

1. **حساسات التربة:** سجّلي ADC الخام للحساس في الهواء (جاف)، ثم في كوب ماء (مبلل). ضعي القيمتين في `SOIL_DRY_RAW` و`SOIL_WET_RAW` في `sensor_node.ino` (ESP32 #1)، ثم أعيدي الرفع.
2. **الصمامات:** وصّلي كهرباء المضخة. شغّلي كل منطقة 5 ثوانٍ، وتأكدي أن الماء يخرج في المنطقة الصحيحة. هذا يكشف أي خطأ في توصيل المرحلات.
3. **تدفق المضخة:** شغّلي منطقة 30 ثانية في وعاء مدرّج، وأدخلي اللترات في الحاسبة. ضعي الناتج في `PUMP_FLOW_LPM`، وأعيدي تشغيل الـBackend.
4. **ثوانٍ لكل 1%:** شغّلي كل منطقة 20 ثانية، وانتظري دقيقتين، واقسمي 20 على مقدار ارتفاع الرطوبة. احفظي الناتج من الحقل الخاص به.

## 6. اختبار إيقاف المطر على العتاد (Phase 24)

1. انتظري حتى تبدأ منطقة بالري، أو شغّلي منطقة 60 ثانية من قسم الصيانة.
2. رشّ ماء على لوحة المطر.
3. خلال 3 إلى 5 ثوانٍ تقريبًا (3 ث تأكيد المطر + ثانية استعلام): يُسمع صوت المرحل، وتتوقف المضخة، ويُغلق الصمام، وتتحول اللوحة إلى "قفل المطر"، ويُظهر جدول "عمليات الري" أن التشغيل أُلغي بسبب المطر.
4. جفّف اللوحة بمنديل. بعد 5 دقائق من الجفاف المتصل يُرسل "توقف المطر"، ثم تبدأ فترة الانتظار، ثم تعود عقدة التشغيل للقرار بقراءات التربة الجديدة.

## 7. قبل العرض

- شغّلي النظام **قبل 3 ساعات على الأقل** حتى يتجمع تاريخ قراءات المحطة ويبدأ التنبؤ.
- في `backend/.env`: `RAIN_COOLDOWN_MINUTES=2` حتى يرى الحكام الدورة كاملة.
- لا تستخدمي قاعدة البيانات الحقيقية لاختبار `npm run e2e`، فهو يمسح القراءات (`docs/test-plan.md`).

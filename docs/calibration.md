# المعايرة (Calibration)

النظام لا يحتوي Flow sensor، لذلك كل كمية ماء يعرضها **تقديرية**:

```
الماء التقديري (لتر) ≈ معدل تدفق المضخة (لتر/دقيقة) × زمن التشغيل (دقيقة)
```

هذه ليست قياسًا. إذا تغير ضغط الماء أو انسد الأنبوب، يتغير الرقم الحقيقي والنظام لا يعرف.

## 1. معدل تدفق المضخة (PUMP_FLOW_LPM)

1. ضعي مخرج الأنبوب في وعاء مدرّج.
2. شغّلي المضخة 30 ثانية مع صمام واحد مفتوح.
3. قيسي الكمية. كرري 3 مرات لكل منطقة، وخذي المتوسط.
4. التدفق = (الكمية باللتر ÷ 30) × 60.
5. اكتبي القيمة في `backend/.env`:

```
PUMP_FLOW_LPM=1.8
```

أعيدي تشغيل الـBackend بعد التعديل. القيمة تُرسل تلقائيًا إلى ESP32 #2 مع كل استعلام، فتحسب اللترات في سجل القرارات بنفس التدفق، ولا حاجة لإعادة رفع الكود.

## 2. حساسات التربة (DRY / WET) — على ESP32 #1

قيمة ADC الخام لكل حساس تظهر في عمود "ADC الخام" في قسم **الصيانة والمعايرة** باللوحة، وفي سطر `[frame]` على Serial Monitor لعقدة الحساسات.

1. الحساس في الهواء أو في تربة جافة تمامًا: سجلي القراءة → `SOIL_DRY_RAW`.
2. الحساس في كوب ماء حتى الخط المرسوم عليه (لا تغمري الدائرة): سجلي القراءة → `SOIL_WET_RAW`.
3. ضعي القيم لكل حساس على حدة في `esp32/sensor_node/sensor_node.ino`:

```cpp
int SOIL_DRY_RAW[3] = {2900, 2900, 2900};   // المنطقة 1، 2، 3
int SOIL_WET_RAW[3] = {1300, 1300, 1300};
```

ثم أعيدي رفع الكود على ESP32 #1. الحساس السعوي يعطي رقمًا **أعلى** كلما كانت التربة **أجف**.
عايري والأسلاك بطولها النهائي، لأن طول السلك يغيّر القراءة قليلًا.

## 3. ثواني كل 1% (seconds_per_percent) لكل منطقة

1. اسقي المنطقة 20 ثانية.
2. انتظري دقيقتين حتى يتوزع الماء.
3. ارتفاع الرطوبة مثلًا 8%: `seconds_per_percent = 20 ÷ 8 = 2.5`.
4. احفظيها من حقل "ثوانٍ لكل 1% رطوبة" في قسم الصيانة، أو:

```bash
curl -X PATCH http://localhost:3000/api/admin/zones/1 \
  -H "Content-Type: application/json" -H "x-admin-key: <ADMIN_API_KEY>" \
  -d '{"seconds_per_percent": 2.5, "target_moisture": 40, "critical_moisture": 22}'
```

## 4. الهدف والحد الحرج لكل منطقة

القيم الافتراضية في `database/seeds/001_seed.sql` نقطة بداية للعرض. عقدة التشغيل تقرأ الهدف والحد الحرج وseconds_per_percent من الـBackend كل ثانية، فأي تعديل يُطبق فورًا بلا إعادة رفع للكود. الهدف يختلف حسب النبات ونوع التربة. الشرط الوحيد الذي تفرضه قاعدة البيانات: الحد الحرج أقل من الهدف.

## لوحة المطر MH-RD (RAIN_DRY_RAW / RAIN_WET_RAW) — على ESP32 #1

قراءة AO تظهر في سطر `[frame]` على Serial Monitor لعقدة الحساسات: `(AO 4095, wet 0%, DO dry)`.

1. اللوحة **جافة ونظيفة**: سجّل قيمة AO ← `RAIN_DRY_RAW` (غالبًا قريبة من 4095).
2. رشّ اللوحة بالماء حتى تتغطى خطوطها: سجّل AO ← `RAIN_WET_RAW` (غالبًا بين 1000 و2000).
3. اكتب القيمتين في `esp32/sensor_node/sensor_node.ino`، ثم أعد الرفع:

```cpp
int RAIN_DRY_RAW = 4095;
int RAIN_WET_RAW = 1500;
```

4. تأكد: قطرتان على اللوحة يجب أن تعطي `wet` فوق 15% (المستوى 1 = مطر). إذا لم تصل، قرّب `RAIN_WET_RAW` من `RAIN_DRY_RAW`.
5. البرغي الأزرق على الموديول: لفّه حتى يضيء LED الموديول مع قطرتين، وينطفئ واللوحة جافة. هذا يضبط DO (التأكيد الإضافي).

حدود المستويات في الكود (`RAIN_LEVEL_PCT`): 15% مطر خفيف، 40% متوسط، 70% غزير.
